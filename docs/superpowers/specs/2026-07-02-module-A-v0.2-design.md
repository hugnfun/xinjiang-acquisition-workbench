## 2. LLM Provider 抽象（关键复用）

每个 LLM 阶段独立配置，默认值按场景定，env 可切本地/DeepSeek。

### 2.1 阶段 → 默认 provider

| 阶段 | 默认 provider | 模型 | 理由 |
|---|---|---|---|
| 打标 labeling | DeepSeek | deepseek-v4-pro | 高频+要稳，v0.1 已验证 |
| 问题过滤/归一化 | 本地 | qwen3.6:27b-q4_K_M | 简单判断，省 token |
| 簇命名 | 本地 | qwen3.6:27b-q4_K_M | 文本归纳，本地够 |
| 合成库提炼 | 本地 | qwen3.6:27b-q4_K_M | 免费；质量不够可切 DeepSeek |
| embedding | 本地 | qwen3-embedding:latest | 只能本地 |

### 2.2 配置扩展（config.py）

在现有 TEXT_*/VISION_* 之外，加一组通用「文本任务」provider，可复用给问题池/合成库：
```python
# 通用文本任务 provider（问题过滤/归一化/命名/合成提炼默认用本地）
TASK_MODEL = os.environ.get("TASK_MODEL", "qwen3.6:27b-q4_K_M")
TASK_API_BASE = os.environ.get("TASK_API_BASE", "http://localhost:11434/v1")
TASK_API_KEY = os.environ.get("TASK_API_KEY", "ollama")

# embedding
EMBEDDING_MODEL = os.environ.get("EMBEDDING_MODEL", "qwen3-embedding:latest")
EMBEDDING_API_BASE = os.environ.get("EMBEDDING_API_BASE", "http://localhost:11434/v1")
EMBEDDING_API_KEY = os.environ.get("EMBEDDING_API_KEY", "ollama")

# 聚类阈值（余弦相似度，>此值连通成簇）
CLUSTER_SIMILARITY_THRESHOLD = float(os.environ.get("CLUSTER_SIMILARITY_THRESHOLD", "0.78"))
```

切 DeepSeek：`TASK_API_BASE=https://api.deepseek.com/v1 TASK_API_KEY=sk-... TASK_MODEL=deepseek-v4-pro`。

### 2.3 client 复用
- 文本任务统一调 `openai` SDK 的 `chat.completions`（本地 27b 通过 Ollama 的 OpenAI 兼容接口）
- embedding 调 `openai` SDK 的 `embeddings.create`（Ollama 支持）
- 复用 `labeling._parse_labels` 容错解析本地模型输出（本地模型 JSON 遵循度不如 DeepSeek，容错更重要）

## 3. 数据模型（新增 3 表）

### 3.1 question（单条问题）
```
id, normalized_text(归一化后), raw_text(原文),
source_ref(回溯: comment_id), source_type='comment',
embedding(BLOB: 向量), cluster_id(FK, nullable),
created_at
```
关键：`source_ref` 回溯评论 → 杜绝幻觉，UI 可点回原文。

### 3.2 question_cluster（问题簇）
```
id, name, description, question_count(冗余计数), created_at
```

### 3.3 asset（合成物）
```
id, type(title|selling_point|hook|cta), text,
derived_from(JSON: [material_id, ...]), tags(JSON: 适用标签),
disliked(bool, default false), created_at
```
关键：`derived_from` 记录从哪些素材提炼 → 未来内容生成可回溯。

### 3.4 不改的表
material / material_tag / comment / tag_* 全不改，复用。

## 4. 问题池冷启动流程

```
1637 条 Comment (is_reply=False 的优先，减少噪音)
   ↓ Stage 1: 过滤"是不是用户问题"
      TASK_MODEL (默认本地27b), 批量每批~20条, JSON mode
      prompt: "判断这些评论哪些是用户在问问题/求助"
      → 是问题的进 question 表 (raw_text=评论, source_ref=comment_id)
      不是的丢弃(如"那没事""好的")
   ↓ Stage 2: 归一化
      TASK_MODEL, 每批~20条
      prompt: "把这些问题归一化(同义合并), 输出 normalized_text"
      → question.normalized_text
   ↓ Stage 3: embedding
      EMBEDDING_MODEL (本地 qwen3-embedding)
      → question.embedding (BLOB, numpy float32 序列化)
   ↓ Stage 4: 聚类 (纯 numpy)
      算 N×N 余弦相似度矩阵
      相似度 > CLUSTER_SIMILARITY_THRESHOLD (0.78) 连通成簇
      → 建 question_cluster 行, question.cluster_id 赋值
      单独问题(无相似)自成一簇
   ↓ Stage 5: 命名
      TASK_MODEL (本地27b), 对每个簇取前5个样本问题
      prompt: "给这组问题起一个简短分类名"
      → question_cluster.name + description
   ↓ 落库完成, UI /questions 可见
```

**Stage 1/2 批处理**：1637 条评论，每批 20 条，约 82 批。本地 27b 每批几秒，冷启动全程约 10-20 分钟。job 化，UI 在 `/jobs` 看进度，可中断重跑（已处理的不重复）。

**容错**：每批 try/except，失败的评论跳过记 JobLog，不阻断整批（复用 label.py 的 per-item 模式）。

## 5. 合成库提炼流程

```
前置: 30 篇素材已打标 (material_tag 非空)
   ↓ 用户在 /materials 多选素材, 或按标签筛 (如"风景震撼+伊犁")
   ↓ 点"提炼合成物" → POST /synthesis/extract
      body: {material_ids: [...], types: [selling_point, hook, cta, title]}
   ↓ TASK_MODEL (默认本地27b), 一次调用, JSON mode
      prompt = 选中素材的 标题+正文+现有标签 + few-shot示例
      → {selling_points:[...], hooks:[...], ctas:[...], titles:[...]}
   ↓ 每条写 asset 表:
      type, text, derived_from=[素材id], tags=[选中素材的公共标签]
   ↓ UI /synthesis 四 tab 可见, 可编辑/删除/标记不喜欢
```

**质量兜底**：本地 27b 提炼质量不够时，env 切 DeepSeek 重跑（provider 抽象保证）。

## 6. UI 视图（新增 2 个，复用 tab 框架）

### 6.1 /questions — 问题池
```
左: cluster 列表 (按 question_count 排, 可重命名)
中: 选中簇的问题列表 (按 raw_text, 显示 source_ref 链接)
右: 问题详情 + "回溯原文" (点链接跳回 /materials 该笔记的评论)
操作: 重命名簇 (PUT /clusters/{id})
```

### 6.2 /synthesis — 合成库
```
四 tab: 标题 | 卖点 | 钩子 | CTA
顶部: "提炼合成物" 按钮 → 弹素材多选 → 提炼
每条卡片: text + 适用标签 + 来源素材链接 + [编辑][删除][👎不喜欢]
操作: POST /synthesis/extract, PUT /assets/{id}, DELETE /assets/{id}
```

### 6.3 tab 框架扩展
现有 `[素材库][任务中心]` → `[素材库][问题池][合成库][任务中心]`。

## 7. API 路由（新增）

```
# 问题池
POST   /jobs/question-pool        触发冷启动 job
GET    /questions                 列表(可按 cluster_id 筛)
GET    /questions/clusters        簇列表(含 question_count)
PUT    /clusters/{id}             重命名簇
GET    /clusters/{id}/questions   簇下问题

# 合成库
POST   /synthesis/extract         body: {material_ids, types} → 触发提炼(同步或job)
GET    /assets?type=...           列表(按 type 筛)
PUT    /assets/{id}               编辑 text / disliked
DELETE /assets/{id}
```

复用 `/jobs` 查 job 状态（问题池 job 走 queue，合成提炼可同步小批量）。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 本地 27b 量化版 JSON 遵循度差 | 复用 _parse_labels 容错；prompt 强约束 JSON；失败批次记 log 跳过 |
| 27b 提炼合成库质量平淡 | provider 抽象，env 切 DeepSeek 重跑；本次先验证管线 |
| 1637 条冷启动耗时长 | job 化 + UI 进度 + 可中断重跑（已处理跳过） |
| numpy 聚类阈值 0.78 不准 | env 可调；UI 可重命名簇兜底 |
| 打标没跑通导致合成库无料 | 问题池不依赖打标，先做；合成库 job 检查 material_tag 是否为空，空则报错提示先打标 |

## 11. 验收标准

1. `DEEPSEEK_API_KEY` 设好后，GUI 点批量打标 → 30 篇出 ai_text/ai_vision 标签
2. 触发问题池冷启动 → 约 10-20 分钟完成 → `/questions` 见簇+问题
3. 簇有 AI 命名（如「季节·最佳时间」），点簇见问题列表，点问题见来源评论
4. `/materials` 多选素材 → 提炼 → `/synthesis` 见卖点/钩子/CTA，每条可点回来源素材
5. 全测试通过 pristine；`npm run build` + `cargo build` 干净
6. provider 切换：改 env 即可把某阶段从本地切 DeepSeek，不用改代码
